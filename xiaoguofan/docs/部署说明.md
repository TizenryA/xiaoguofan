# 小锅饭部署说明

## 环境与目录

Linux + systemd + Docker Engine，Python 3.11+、venv/pip、Git。以下目录固定于安装脚本：

- `/data/aistudio-portal-src`：仅门户源码，**不是整个 Fork 根目录**。
- `/data/aistudio-portal`：数据库、主密钥、管理密码和配置。
- `/run/aistudio-portal/broker.sock`：门户与受限 Docker broker 的 Unix socket。

Docker 仅由 broker 使用，门户进程不直接访问 Docker socket。请勿把 broker 暴露成公共 TCP 服务。

## 安装

在仓库根目录执行（安装前先检查脚本；下列命令需要 root）：

```bash
sudo install -d -m 755 /data/aistudio-portal-src
sudo cp -a xiaoguofan/portal xiaoguofan/deploy xiaoguofan/requirements.txt xiaoguofan/pyproject.toml xiaoguofan/uv.lock /data/aistudio-portal-src/
sudo install -d -m 700 /data/aistudio-portal
```

写入你的公共访问地址，示例域名必须替换成自己的：

```bash
printf '%s\n' 'https://ais.example.com/lite' | sudo tee /data/aistudio-portal/origin >/dev/null
sudo python3 /data/aistudio-portal-src/deploy/install.py
```

脚本自动建立服务用户、虚拟环境、随机管理密码与两个 systemd 服务：

- `aistudio-portal`：门户服务，默认端口 8088。
- `aistudio-portal-broker`：受限 Unix socket worker 管理服务。

初次管理凭据位于 `/data/aistudio-portal/credentials.json`，仅在服务器本地以受控方式查看，不要公开发送。自动生成的 `portal.env` 包含管理密码，切勿提交 Git。

**注意：安装脚本默认监听 `0.0.0.0:8088`。不要直接对公网开放该端口。** 同机反代应改成回环监听；跨机反代必须先限制来源 IP 或使用私有网络。端口、Docker 网络、防火墙请按自身环境检查。

## HTTPS 反向代理

同机 Caddy 示例（8088 若已改回环则保持如此）：

```caddyfile
 ais.example.com {
    reverse_proxy 127.0.0.1:8088
 }
```

保留 URL 路径，不要 strip `/lite`。设置 `PORTAL_ORIGIN=https://ais.example.com/lite` 后：

- 普通入口：`https://ais.example.com/lite`
- 后台入口：`https://ais.example.com/guanlimanage`
- OpenAI Base URL：`https://ais.example.com/lite/v1`
- Discord 回调：`https://ais.example.com/lite/auth/discord/callback`

若 origin 不带路径，则用户根入口 `/`、后台 `/admin`、兼容 API `/v1`。先检查 HTTPS、Cookie 路径和管理登录，再开放注册。

## 配置 Discord

1. 创建自己的 Discord OAuth 应用。
2. 填写后台显示的精确回调地址。
3. 后台填写 Client ID、Client Secret。
4. 根据需要设置社区屏蔽和朋友白名单。
5. 确认配置正确后开启公共登录。

白名单仅豁免社区屏蔽，仍需要 Discord 登录，不授予管理权限。更改访问规则会使旧验证失效。

## 上游 worker

固定镜像见 `portal/workers.py`：

```text
ghcr.io/mag1cfall/aistudio2api:v0.2.12@sha256:455673a62d02b85d019c856c6a98e20d05b99ff80ffbb1f8b24623873f4de96e
```

新用户首次调用会启动其独立容器。默认每个 worker 限制 650MB 内存和 0.7 CPU；请按主机资源限制并发和 worker 总数。worker 使用临时存储，闲置回收；账号主凭据在门户数据库中加密保存。启动模型列表通过不等于生成一定成功。

## 备份与升级

- 备份数据库须用 SQLite backup API 或停服务后复制，不能仅复制活动 WAL 数据库主文件。
- **数据库与 `master.key` 必须一起备份**，否则无法解密已有账号。
- 同时保护 `credentials.json`、`portal.env`、origin 和备份目录权限。
- 升级前备份，再替换源码、安装依赖，重启两个服务。
- 重启 broker 会结束旧的临时 worker；客户端可能需重试。
- 更新 origin 后重新运行安装脚本以同步环境并重启服务。

## 测试与扩展

源码测试使用 uv；测试不需要生产凭据：

```bash
cd xiaoguofan
uv sync --dev
uv run pytest -q
uv run ruff check --select E9,F,I portal tests
node --test tests/extension-core.test.cjs
python3 deploy/build-extension.py
```

扩展 ZIP 仅由明确列表内源码打包，桌面 Chrome / Edge 可加载解压目录。手机 Chrome 不支持桌面扩展，安卓可上传已有 JSON。扩展/JSON 是敏感登录会话，不是普通 Gemini API Key。
