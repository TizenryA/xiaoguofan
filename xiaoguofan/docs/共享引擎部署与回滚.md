# 小锅饭 1.0 共享引擎：部署与回滚

> 这份文档只写给运维看。**部署前必须由站长确认**；本分支没有在任何服务器上执行过。

## 这次变了什么（运维视角）

| 0.9.22 | 1.0 |
|---|---|
| 每个用户一个 worker 容器（冷启动、闲置回收） | 一个常驻引擎容器 `xiaoguofan-engine`，所有用户共用进程 |
| 每个用户只用自己的账号 | **不变**：门户给每个请求加上可信的账号范围头，引擎强制只在该用户自己的账号里选号、切号 |
| 冷却时排队等待 | 不排队：同一用户的其他账号可用就立刻切换；全部冷却时立刻告诉用户北京时间几点恢复 |
| 防截断在门户里起短进程 | 独立常驻服务 `anti/server.js`（unix socket），连不上时自动退回短进程并在后台告警 |
| 告警只在日志里 | 后台「告警」列表（只有管理员能看到） |

数据库只新增表（`engine_accounts`、`response_owners`、`alerts`），不改、不删任何已有用户、账号、Key、记录。

## 资源规划（依据：8 vCPU / 15Gi 内存 / 2Gi swap；157 用户 / 68 账号 / 183 Key）

| 项 | 默认值 | 环境变量（broker 进程） |
|---|---|---|
| 引擎内存硬上限 | 8g | `PORTAL_ENGINE_MEMORY` |
| Go 软上限 | 7GiB | `PORTAL_ENGINE_GOMEMLIMIT` |
| 引擎 CPU | 6 | `PORTAL_ENGINE_CPUS` |
| 常驻热账号 VM | 16 | `PORTAL_ENGINE_WARM_WORKERS` |
| 同时活跃账号 VM 上限 | 24 | `PORTAL_ENGINE_MAX_ACTIVE` |
| 单账号并发 | 2 | `PORTAL_ENGINE_PER_ACCOUNT` |
| 并行预热 | 4 | `PORTAL_ENGINE_WARM_STARTUP` |
| 引擎端口（仅 127.0.0.1） | 2049 | `PORTAL_ENGINE_PORT` |
| 全站同时生成 | 48 | 后台设置 `engine_concurrency` |
| 每用户同时生成 | 4 | 后台设置 `user_concurrency` |
| 每分钟次数限制 | 关闭 | 后台设置 `rate_limit_enabled` |
| 门户在途请求体总量 | 256MB | `PORTAL_BODY_BUDGET_MB` |

这些是估算值，**没有用真实账号压测过**。上线后看后台实时面板的内存/活跃数，再调整。slice 保持 `MemoryHigh=9G / MemoryMax=10G`。

## 部署前准备（不停服）

以下以生产数据目录 `/opt/xiaoguofan/data` 为例；先用 `systemctl list-units 'xiaoguofan*' 'aistudio-portal*'` 确认实际服务名和目录。

1. **备份（必须先做）**
   ```bash
   DATA=/opt/xiaoguofan/data
   STAMP=$(date +%Y%m%d-%H%M%S)
   sudo install -d -m 700 /root/xgf-backup-$STAMP
   sudo sqlite3 $DATA/portal.db ".backup '/root/xgf-backup-$STAMP/portal.db'"
   sudo sqlite3 /root/xgf-backup-$STAMP/portal.db 'PRAGMA integrity_check'   # 必须输出 ok
   sudo tar -C $DATA --exclude=portal.db --exclude=portal.db-wal --exclude=portal.db-shm \
        -czf /root/xgf-backup-$STAMP/data-dir.tar.gz .                      # 含 master.key、credentials.json
   sudo cp -a /etc/systemd/system/xiaoguofan* /root/xgf-backup-$STAMP/ 2>/dev/null || true
   ```
   `portal.db` 和 `master.key` 必须一起保存，缺一不可。

2. **只读预检**（在副本上演练，原库不动）
   ```bash
   sudo /path/to/venv/bin/python scripts/migrate_shared_engine.py --data $DATA --check
   ```
   看三项：`before` 与 `after_on_copy` 相同；`integrity_on_copy` 为 `ok`；`duplicate_email_conflicts`（同一个 Google 邮箱被不同用户导入，邮箱已打码）。冲突账号上线后按「最早导入者」归属，后来者在「我的账号」里看到冲突提示，后台出现告警——需要站长联系当事人处理，**系统不会把一个账号给两个人用**。

3. **构建镜像**（在构建机，不在生产机上编译）
   ```bash
   python3 xiaoguofan/packaging/build.py            # 产出 worker(=引擎) 与 portal 镜像 tar
   ```
   引擎镜像标签 `xiaoguofan-worker:1.0.0`（可用 `PORTAL_ENGINE_IMAGE` 覆盖）。

## 部署（停机窗口约 5 分钟）

1. 停门户和 broker（旧 worker 容器会被 broker 清理）。
2. 导入镜像：`docker load -i worker.tar.gz`。
3. 替换门户代码（含新的 `anti/` 目录），安装依赖。
4. 执行迁移（会再做一次 SQLite 在线备份并核对行数）：
   ```bash
   sudo /path/to/venv/bin/python scripts/migrate_shared_engine.py --data $DATA
   ```
   任何一项核对失败脚本都会退出并打印恢复命令。
5. 防截断常驻服务（发行包安装器会自动生成；手工部署用下面的单元）：
   ```ini
   # /etc/systemd/system/xiaoguofan-anti.service
   [Unit]
   Description=Xiaoguofan anti-truncation service
   [Service]
   Slice=xiaoguofan.slice
   User=xiaoguofan
   Group=xiaoguofan
   RuntimeDirectory=xiaoguofan-anti
   RuntimeDirectoryMode=0750
   ExecStart=/usr/bin/node /path/to/xiaoguofan/anti/server.js /run/xiaoguofan-anti/anti.sock
   MemoryMax=512M
   PrivateNetwork=true
   ProtectSystem=strict
   NoNewPrivileges=true
   Restart=on-failure
   [Install]
   WantedBy=multi-user.target
   ```
   门户服务加：`Environment=XGF_ANTI_SOCKET=/run/xiaoguofan-anti/anti.sock`、`Wants=xiaoguofan-anti.service`。
6. 门户服务加：`Environment=PORTAL_TRUSTED_PROXIES=179.253.243.0/32`（DMIT 入口），门户内存上限调到 768M。
7. 启动顺序：anti → broker → 门户。broker 启动后会创建 `xiaoguofan-engine` 容器；门户在后台把所有启用的账号导入引擎。
8. DMIT 入口：把 `deploy/dmit/Caddyfile` 放到 DMIT（设置 `XGF_ORIGIN_HOST`、`XGF_ORIGIN_ADDR`），生产 Caddy 合并 `deploy/dmit/prod-caddy-snippet.caddyfile`（trusted_proxies、flush_interval -1、长超时）。

## 上线后检查

```bash
docker ps --filter name=xiaoguofan-engine           # Up，且只有这一个引擎容器
curl -s 127.0.0.1:<门户端口>/health                  # {"status":"ok"}
systemctl status xiaoguofan-anti                    # active
```
后台：实时面板「引擎在线」、账号状态多数为「可用」、告警列表没有「引擎不可用」。
用一个测试用户的 Key 调一次流式对话，确认首字正常、记录里出现耗时和账号。

## 回滚到 0.9.22

新表对旧版无影响，正常回滚**不需要恢复数据库**：

1. 停门户、broker、anti；`docker rm -f xiaoguofan-engine`。
2. 换回 0.9.22 代码和旧 systemd 单元（备份目录里有），`systemctl daemon-reload`。
3. 启动 broker、门户。旧版按需重新起每用户 worker。
4. 只有在迁移脚本报错、或数据异常时才恢复数据库：
   ```bash
   systemctl stop <门户> <broker>
   cp /root/xgf-backup-$STAMP/portal.db $DATA/portal.db && rm -f $DATA/portal.db-wal $DATA/portal.db-shm
   ```
   注意：恢复备份会丢失备份之后新增的记录/账号。

## 已知风险与未验证项

- 引擎没有用真实 Google Cookie 跑过（按约定只用模拟引擎测试），上线首小时请盯后台账号状态和告警。
- 资源规划是估算；24 个同时活跃账号 VM 对应约 6–7GiB 内存，需上线观察。
- 引擎镜像需要在构建机完整编译（SpiderMonkey/libwebp），本地只做了带桩编译和单元测试。
- 账号的套餐（Free/Pro）和可用模型以引擎上报为准；引擎还没上报时按账号登记的套餐过滤模型列表。
- broker 重启会重启引擎容器，期间进行中的请求会中断（与旧版重启 broker 相同）。
