# English UI (i18n)

- Chinese stays the source text and the default. English lives in `portal/static/i18n-en.js`
  (`exact`: Chinese → English; `templates`: entries with `{0}`/`{name}` placeholders, `{0|one|many}` plurals).
- Browser: `portal/static/i18n.js` picks the language (saved choice in `localStorage['xgf-lang']`, else `zh*` → Chinese,
  anything else → English), sets `<html lang>`, and in English translates text nodes and
  `placeholder/title/aria-label/alt` as they appear (also JS-rendered UI, toasts, `alert/confirm`).
  Every `fetch` carries `Accept-Language` for the page language. The toggle (`[data-lang-toggle]`) also
  sets the `xgf_lang` cookie for pages the server renders itself.
- Server: `portal/i18n.py` + `I18nMiddleware` rewrite JSON messages to English when the request asks for it
  (`xgf_lang` cookie, else first `Accept-Language` tag). Portal `/api/*` replies are translated; on `/v1*` and
  `/v1beta*` only error replies (model ids and generated text are never touched). The all-accounts-used-up
  message gives UTC in English (Retry-After unchanged); the CSV export header follows the language.
- Times: Chinese shows Beijing time; English shows the reader's own time zone for clock times, while day
  buckets stay Beijing calendar days (labelled as such).
- Adding a Chinese string: add its English to `i18n-en.js`. `tests/test_i18n.py` fails if any Chinese text in
  the pages, scripts or server messages has no English, or if an English entry no longer exists in the source.
